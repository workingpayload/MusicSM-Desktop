# MusicSM Desktop code map

## Project context

MusicSM's desktop port is a Kotlin/JVM music player with Compose Desktop UI.
YouTube Music supplies metadata through InnerTube; NewPipeExtractor resolves
audio streams; vlcj/libVLC handles playback. Shared mobile business logic lives
in JVM modules, while desktop UI, storage, and native integrations live in
`desktopApp`. Manual dependency injection is used, not Hilt/Dagger.

This map describes the working tree, including the currently uncommitted
animated-artwork and privacy changes. It is a navigation guide, not an audit.
See `README.md` for feature behavior and `PRIVACY-POLICY.md` for service requests
and local-data handling.

## Modules and dependencies

| Module | Dependencies on other modules | Responsibility |
|--------|-------------------------------|----------------|
| `desktopApp` | `domain`, `data`, `motionart`, `innertube` | Compose UI, application wiring, playback, file persistence, desktop integrations |
| `data` | `domain`, `innertube` | Music repositories, YouTube/NewPipe sources, lyrics providers, playlist import |
| `domain` | `motionart` (API dependency) | Models, repository/source contracts, recommendations, matching, playlist sharing |
| `innertube` | None | YouTube Music HTTP client, renderer parsing, response models |
| `motionart` | None | Apple/TIDAL/Vivi animated-artwork lookup, matching, provider caches |

Source roots:

- Desktop: `desktopApp\src\main\kotlin\com\example\musicsmd`
- Shared data: `data\src\main\kotlin\com\example\musicsm\data`
- Shared domain: `domain\src\main\kotlin\com\example\musicsm\domain`
- InnerTube: `innertube\src\main\kotlin\com\example\innertube`
- Motion artwork: `motionart\src\main\kotlin\com\example\motionart`

Paths in the next two sections are relative to the desktop source root.

## Entry points and state

| File | Role |
|------|------|
| `Main.kt` | `main()` initializes `AppGraph`, creates view-model/controllers, starts media keys and update notices, owns the window/tray lifecycle and Compose app shell |
| `AppGraph.kt` | Singleton manual DI root; wires HTTP clients, music/lyrics/import repositories, settings, library, stats, downloads, local files, player, motion art, and updates; initializes NewPipe and Coil |
| `player\AppViewModel.kt` | Navigation/back stack, search/home/detail loading, queue, stream lookup, playback actions, settings synchronization, persistence, prefetch, and listening statistics |
| `nav\Screen.kt` | Screen identities and top-level navigation destinations |
| `settings\SettingsStore.kt` | Persisted settings and settings flow |

`AppViewModel` exposes separate `uiState`, `playback`, and `position` StateFlows.
High-frequency position updates deliberately do not update the broad playback
state; seek and lyric rendering use `player\SmoothPosition.kt`.

## Important execution paths

**Music:** UI actions -> `AppViewModel` -> `MusicSource` / `MusicRepository`.
`AppGraph` supplies `YouTubeMusicSource`, combining InnerTube metadata with
NewPipe extraction. `MusicRepositoryImpl` caches stream URLs using expiry and a
refresh margin. Playback prefers downloads/local files through
`CompositeOfflineSource`, then resolves a network stream and drives
`PlayerController`. The view-model owns queue progression, upcoming-stream
prefetch, and stream invalidation/retry after playback errors.

**Bot-checked networks:** when NewPipe throws `SignInConfirmNotBotException`,
`YouTubeMusicSource` uses `SignedInStreamResolver` (signed-in `WEB_REMIX`
player request with stored cookies) if the user signed in, else throws
`YouTubeSignInRequiredException`, which `AppViewModel` turns into a sign-in
prompt. `BrowserPlayerScript` unscrambles sig/`n` and mints PO tokens in a
headless Edge/Chrome tab.

**Crossfade/Mix:** `AppViewModel` owns a `MixController`, configured from the
`crossfadeMs`/`mixMode` settings. Near a track's end it resolves the upcoming
queue entry, (Mix) decodes tail/head snippets via `VlcSnippetDecoder` and plans
with `TransitionPlanner`, then loads the next track paused and silent on
`PlayerController`'s standby deck. At the hand-off the decks swap,
`AppViewModel.onMixHandoff` advances the queue without reloading, and levels and
bass swap run through per-deck equalizers (`DeckEqualizer`). User track
switches cancel it (`loadSong`), pause/seek end a running blend.

**Lyrics:** playback/settings -> `LyricsController` ->
`LyricsRepositoryImpl` -> configured provider stack -> `LyricsPanel`.
Shared providers cover Apple Music, BiniLyrics, LyricsPlus, SimpMusic, LRCLIB,
KuGou, Unison, and YouTube Music.

**Animated artwork:** playback/settings/visibility -> `MotionArtController` ->
`DesktopMotionArtRepository` -> shared `MotionArtSource` -> Apple/TIDAL/Vivi.
Desktop cache keys include artist/title/album/provider, with 256 entries,
one-hour hits, and 15-minute misses. Lookups are cancellation-aware and only
active for visible Now Playing. `Main.kt` passes window visibility/minimized
state; the rendering/player layer handles silent video and still-cover fallback.
Shutdown disposes the controller and closes the shared motion-art HTTP client.

**Persistence:** application data lives under `~\.musicsm-desktop`, including
settings, library, statistics, downloads, queue, and search-history JSON files.
The desktop file repositories/managers own this storage.

## Build, tests, and packaging

`settings.gradle.kts` declares the five modules. Dependency versions are in
`gradle\libs.versions.toml` (Kotlin 2.3.20, Compose 1.12.1, vlcj 4.11.0).
Modules compile with the JDK 17 toolchain; Gradle's daemon uses JDK 25 as
configured in `gradle\gradle-daemon-jvm.properties`.

```powershell
.\gradlew.bat :desktopApp:run
.\gradlew.bat :desktopApp:test :data:test :innertube:test :motionart:test
.\gradlew.bat :desktopApp:packageMsi "-PpackagingJdk=C:\Program Files\Java\jdk-27"
```

Tests live in each module's `src\test\kotlin` tree and use JUnit 4.
Existing coverage includes lyrics parsing/selection, playlist imports,
InnerTube parsing, artwork matching/providers, desktop artwork lifecycle/cache/
settings/frame layout, search persistence, artwork colors, updates, and VLC
discovery. Native motion-art tests are opt-in; see README for fixture environment
variables and remote-provider opt-in.

`desktopApp\build.gradle.kts` owns version generation, VLC bundling, and Compose
installer configuration. `playback\BundledVlcDirectoryProvider.kt` discovers
the bundled runtime. `.github\workflows\release.yml` builds Windows MSI/macOS
DMG releases. Packaging requires a full JDK with `jpackage` and a VLC source
installation unless bundling is explicitly disabled.
